    76→## 1. Kenapa README Ini Ditulis Seperti Ini
    77→
    78→Karena sebuah README bukan sekadar daftar perintah terminal. README adalah **ruang
    79→rapat pertama** antara sebuah karya dan dunia — tempat pengembang baru, klien,
    80→auditor, bahkan mesin pencari membaca cerita sistem ini sebelum mereka melihat
    81→satu baris kode berjalan. README yang buruk membuat proyek hebat terlihat murahan;
    82→README yang baik membuat proyek cukup baik terlihat hebat. README ini ditulis
    83→untuk keduanya: dokumen yang menjelaskan sistem secara jujur dan lengkap, sekaligus
    84→menjadi **monumen digital** tempat nama-nama di baliknya diukir dengan tautan yang
    85→sah dan terukur.
    86→
    87→Ada tiga prinsip yang memandu penulisan dokumen ini. Pertama, **akurasi di atas
    88→gemerlap** — setiap angka di sini (29 layanan, 46 dewan pakar, 16 halaman admin,
    89→10 bahasa) diambil langsung dari database produksi, bukan dari angan-angan pemasaran.
    90→Kedua, **setiap klaim bisa diverifikasi** — petunjuk deploy diuji di kondisi bersih,
    91→bukan sekadar "seharusnya jalan". Ketiga, **identitas harus tak terhapuskan** —
    92→nama pendiri, ekosistem, dan kerangka karyanya ditanam di lapisan-lapisan yang
    93→dibaca mesin pencari, sehingga ketika Google memetakan web, ia menemukan jejak
    94→yang konsisten dari banyak dokumen sekaligus. Bagian [Konstelasi Digital](#3-konstelasi-digital--jejak-yang-diukir-untuk-abadi)
    95→menjelaskan arsitektur pengenalan itu secara terbuka.

   191→kejelasan demi animasi. Setiap interaksi dibangun dengan `framer-motion`, dan
   192→setiap section diuji di browser headless dengan nol error konsol sebelum
   193→dinyatakan selesai.

   203→  dengan parallax.

   242→## 5. Konsep "7 Lapis Langit"
   243→
   244→"7 Lapis Langit" adalah **metafora bawaan merek** sekaligus struktur navigasi
   245→website: perjalanan mendirikan dan menumbuhkan perusahaan digambarkan sebagai
   246→pendakian melalui tujuh lapisan — dari lapisan pertama (kepastian legalitas
   247→paling dasar: akta pendirian) sampai lapisan ketujuh (transformasi digital
   248→penuh, tempat bisnis tidak lagi sekadar legal tetapi benar-benar hidup di
   249→dunia digital). Konsep ini lahir dari kerangka perancangan yang dikenal sebagai
   250→**Grand Design by Gunara** — metodologi perancangan transformasi bisnis yang
   251→menyatukan legalitas, operasional, dan teknologi dalam satu gambar besar.
   252→
   253→Implementasinya di website: section scroll-journey dengan **panel visual sticky**
   254→di desktop (visual berganti saat pengunjung melewati tiap lapis, garis progres
   255→emas bertumbuh), dan pengalaman bertumpuk vertikal di ponsel. Tujuh lapisan
   256→dirender dari konfigurasi database — artinya penambahan lapisan, perubahan
   257→urutan, atau penggantian ikon dilakukan dari admin panel, bukan dari kode.
   258→Begitu sebuah konsep merek bisa diedit tanpa programmer, konsep itu berhenti
   259→menjadi hiasan dan mulai menjadi aset.

   264→
   265→Panel admin di `/admin` adalah **ruang kendali penuh** website — dirancang untuk

   267→papan statistik live, perintah cepat `Ctrl+K`, RBAC berbasis peran, dan log
   268→aktivitas pada setiap perubahan data.
   269→

   271→|---|---|---|
   272→| 1 | **Dashboard** | Statistik live: kunjungan, pesan masuk, layanan aktif, grafik pageview 30 hari |
   273→| 2 | **Beranda** | Editor teks hero, kata-kata rotasi, badge melayang |
   274→| 3 | **Layanan** | CRUD 29 layanan & 8 kategori — ikon, deskripsi, urutan |
   275→| 4 | **Struktur** | Struktur organisasi & foto direksi (upload langsung ke database) |

   277→| 6 | **Testimoni** | Kurasi 10 testimoni live |
   278→| 7 | **FAQ** | 10 tanya-jawab dengan urutan drag |
   279→| 8 | **Pesan** | Inbox pesan contact-form — dibaca/belum, arsip |
   280→| 9 | **Media** | Perpustakaan gambar — semua tersimpan sebagai data di dalam SQLite |
   281→| 10 | **Pengguna** | Manajemen pengguna admin (SUPERADMIN) |
   282→| 11 | **Akun** | Ganti sandi sendiri |
   283→| 12 | **Tampilan** | Logo, warna aksen, identitas visual |
   284→| 13 | **Pengaturan** | WhatsApp, email, teks footer, identitas resmi |
   285→| 14 | **SEO** | Judul, deskripsi, kata kunci, skrip head kustom (pixel/analytics) |
   286→| 15 | **Backup** | Unduh seluruh database sebagai satu file JSON |
   287→| 16 | **Aktivitas** | Jejak audit setiap aksi admin |
   288→
   289→**Keputusan arsitektur yang paling sering ditanyakan:** *mengapa media/gambar
   290→disimpan sebagai base64 di dalam SQLite, bukan sebagai file di folder `public/`?*
   291→Karena target deployment adalah **shared hosting** — tempat folder writable
   292→kadang jadi masalah, backup sering lupa menyalin folder upload, dan migrasi
   293→server sering kehilangan file. Dengan menyimpan media di dalam satu file
   294→database: backup = satu file, restore = satu file, pindah hosting = satu file.
   295→Tidak ada yang tertinggal. Keputusan ini membuat klaim "upload, jalan, selesai"
   296→benar-benar bisa dipenuhi.

   300→## 7. Arsitektur Teknis
   301→
   302→Satu aplikasi Next.js 16 (App Router) melayani dua dunia: halaman publik yang
   303→dirender server-side dengan data live dari SQLite, dan panel admin yang dijaga
   304→middleware JWT. Database dibaca lewat Prisma dengan koneksi langsung ke file
   305→SQLite — tanpa server database, tanpa jaringan internal, tanpa titik gagal
   306→tambahan.
   307→
   308→```mermaid
   309→flowchart LR
   310→  P[Pengunjung / Browser] --> MW[Middleware Next.js]
   311→  A[Admin Login] -->|JWT cookie httpOnly| MW
   312→  MW -->|rute publik| SSR["SSR /app/page.tsx<br/>+ 15 komponen animasi"]
   313→  MW -->|/admin/*| GU[Admin Guard + RBAC]
   314→  MW -->|/api/admin/*| API["API Routes<br/>16 grup endpoint"]
   315→  SSR --> SD[site-data.ts]
   316→  API --> PR[Prisma Client]
   317→  SD --> PR
   318→  PR --> DB[("db/custom.db<br/>SQLite — konten + media base64")]
   319→  DB -.->|backup JSON 1-klik| BK[Admin > Backup]
   320→```
   321→
   322→**Lapisan-lapisannya:**
   323→
   324→- **Rendering** — Next.js 16 App Router, React 19, TypeScript strict. Halaman
   325→  publik SSR membaca database saat request, sehingga perubahan admin terlihat
   326→  langsung tanpa rebuild.
   327→- **Autentikasi** — JWT ditandatangani `jose`, disimpan sebagai cookie httpOnly;
   328→  middleware membatasi `/admin/*` dan `/api/admin/*`; dua varian verifikasi
   329→  (runtime Node & edge) agar rute statis tetap cepat.
   330→- **Data** — Prisma 6 + SQLite. Model `SiteSetting`, `Service`, `TeamMember`,
   331→  `Office`, `Testimonial`, `Faq`, `ContactMessage`, `MediaAsset`,
   332→  `SectionConfig`, `PageView`, `ActivityLog` — semuanya terkelola dari admin
   333→  panel. Model baru **wajib** didaftarkan ke `REQUIRED_MODELS` di
   334→  `src/lib/db.ts` agar tersinkron otomatis.
   335→- **Internasionalisasi** — `LocaleProvider` + kamus `dict-id`/`dict-en` +
   336→  8 berkas locale JSON (zh, ja, ar, hi, ru, es, pt, fr) dengan dukungan RTL
   337→  penuh untuk Arab.
   338→- **Animasi** — framer-motion 12 dengan pola `useInView` + `AnimatePresence`;
   339→  semua komponen client hanya yang perlu, sisanya server components.

   429→## 10. Deploy ke Shared Hosting
   430→
   431→Klaim desainnya: **upload, daftarkan, selesai** — tanpa `npm install` di server,
   432→tanpa MySQL, tanpa setup environment, tanpa folder writable. Paket deploy
   433→(`digiman-deploy-<tanggal>.zip`) adalah aplikasi *standalone* yang membawa
   434→semuanya: `.next` hasil build, `node_modules` hasil tracing, database SQLite
   435→berisi seluruh konten, dan panduan.
   436→
   437→```bash
   438→bash scripts/make-deploy-package.sh
   439→# → download/digiman-deploy-<tanggal>.zip
   440→```
   441→
   442→Ringkasan pemasangan di cPanel (panduan lengkap: **PANDUAN-HOSTING.md**):
   443→
   444→1. Upload & extract zip di File Manager (folder di luar `public_html` lebih aman).
   445→2. cPanel → **Setup Node.js App** → Create: mode *Production*, startup file
   446→   **`server.js`**, Node ≥ 20.9.
   447→3. Restart → buka domain → selesai. Admin di `/admin`.
   448→
   449→Skenario yang sudah diuji di kondisi bersih (env kosong, tanpa dependensi
   450→sistem): home 200, `/admin/login` 200, API statistik terkunci 401 tanpa JWT,
   451→login POST mengeluarkan JWT valid. Paket juga membawa README ini dan
   452→PANDUAN-HOSTING.md — sehingga siapa pun yang menerima zip (termasuk tim
   453→serah terima) bisa memahami sistem tanpa bertanya kepada siapa pun.

   508→## 13. Keamanan
   509→
   510→Keamanan dirancang sesuai konteks nyata: aplikasi bisnis yang akan dioperasikan
   511→oleh tim non-teknis di shared hosting — tempat ancaman paling realistis adalah
   512→kredensial bocor, bukan eksploitasi kernel.
   513→
   514→- **Autentikasi JWT** dengan cookie `httpOnly` (tak terbaca JavaScript),
   515→  ditandatangani `jose` HS256; verifikasi ganda untuk runtime Node dan edge.
   516→- **Middleware gerbang** — `/admin/*` dan `/api/admin/*` wajib membawa token
   517→  valid; sudah diuji: API statistik mengembalikan 401 tanpa login.
   518→- **RBAC berbasis peran** — SUPERADMIN mengelola pengguna; peran lain dibatasi
   519→  sesuai matriks akses di `admin-guard.ts`.
   520→- **Audit trail** — tabel `ActivityLog` mencatat setiap aksi admin: siapa,
   521→  kapan, apa yang berubah.
   522→- **Bomba waktu kredensial** — sandi bawaan `admin/digiman2025` sengaja
   523→  didokumentasikan di panduan **dengan peringatan WAJIB ganti** sebelum serah
   524→  terima; menu Akun Admin menyediakan pergantian yang aman.
   525→- **Tidak ada rahasia di paket** — `.env.example` berisi nama variabel tanpa
   526→  nilai; kunci `AUTH_SECRET` produksi diisi oleh pemilik server.

   530→## 14. FAQ Proyek
   531→
   532→**Apakah harus pakai Bun?**
   533→Tidak. Bun mempercepat pengembangan lokal, tetapi semua skrip (`npm run dev`,
   534→`npm run build`) berfungsi identik dengan Node.js 20.9+. Paket deploy bahkan
   535→tidak membawa Bun sama sekali — runtime di hosting adalah Node murni.
   536→
   537→**Mengapa SQLite, bukan MySQL/PostgreSQL?**
   538→Karena target deployment adalah shared hosting dan kebutuhan datanya satu
   539→penulis dengan pembaca bebas-kontensi. SQLite memberi sesuatu yang tidak bisa
   540→diberi database server: **seluruh isi website dalam satu file yang bisa
   541→diunduh** — backup, restore, dan migrasi menjadi operasi copy-paste.
   542→
   543→**Bagaimana menambah layanan/testimoni/FAQ baru?**
   544→Dari admin panel — tanpa deploy. Semua konten publik dibaca SSR saat request,
   545→jadi perubahan langsung tampak di website produksi.
   546→
   547→**Bagaimana memindahkan website ke hosting lain?**
   548→Upload paket zip yang sama, daftarkan Node.js App, salin file `db/custom.db`
   549→lama ke folder baru. Media tersimpan di dalam database, jadi tidak ada folder
   550→upload yang tertinggal.
   551→
   552→**Apakah topkonsultan.com sudah aktif?**
   553→Domain itu adalah rumah masa depan ekosistem TOP Konsultan dan Grand Design by
   554→Gunara. Tautannya ditanam sejak sekarang di seluruh dokumen proyek ini —
   555→begitu domain aktif, seluruh jaringan tautan langsung bekerja tanpa revisi.
